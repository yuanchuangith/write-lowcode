# Look / Write 优化交付记录（2026-10-27）

本轮实现来源检查提速、诊断分页分析缓存、有限只读补查及指定 Schema 关系实时验证。性能结论来自本机离线夹具；没有连接业务数据库、保存业务草稿或发布业务动作，不代表生产准确率或真实端到端业务已经验证。

## 实现与保留的约束

Write 先探测 Node 身份、读取当前 Git 来源，再执行紧邻缓存使用的完整字节校验。有效注册表热命中减少一次扫描；冷加载、缓存损坏重建和真实 Node 调用前后仍校验来源。已有实例不重新绑定变化后的来源。Git root、HEAD、branch 合为一次查询，保留 status/diff 原始字节、工作区哈希和 detached HEAD 语义。

Look 的 `inspect_component_filters`、`trace_dynamic_exception` 复用进程内分析快照。缓存按数据源/账号作用域、工具、分析器版本、参数和证据隔离，最多32项、单项8 MiB、累计序列化64 MiB、闲置5分钟淘汰。每次请求仍使用当前连接重放原读取谓词，核对权限、空候选、动作及历史版本、内容、删除状态和草稿/发布副本。失败不返回旧证据；淘汰后重建并校验游标。UTF-8 哈希与稳定排序不消除业务歧义。容量限制是序列化体积限制，不是 Python 堆内存硬上限。

两库增量提供 `evidence_gaps` / `fallback`，保留原有状态、错误码、完整性标志和 `next_read`。指导字段参与输出预算，不进入业务签名、审批绑定或诊断证据指纹。技能按固定路径编排，同一问题最多额外3次只读调用、累计30秒，不重复失败路径；更严格的图谱预算继续生效。无可控超时的调用只列建议。

Schema 四项源/目标表列明确且 `force_live=true` 时，直接读取指定表列、完整目标唯一键及聚合匹配，不依赖全库刷新。验证前后检查本机否决；策略不可读、唯一键证据不足、类型不兼容或超时均不能通过。成功只证明指定关系，返回 `verification_scope=explicit_target`、`candidate_group_complete=false`、`persisted=false`，不写可信关系快照。`live_timeout_ms` 是查询工作预算，不能硬取消建连、连接池等待、ping 或归还；自动兜底还需外层可控墙钟超时，否则只给建议。

CPM 刷新失败可返回明确标旧的快照候选，不能证明当前运行状态。源码某层失败保留健康层，旧索引行号不作当前位置。缺生产/页面证据时继续独立静态工作，并列出最小补证请求。

Write 保留 `unverified` 原有人工复核规则；`failed`、完整旧值缺失、编译失败、来源漂移继续阻断。没有新增通用工具执行接口，没有实现源码索引增量化、图查询改造或 Node/C# 编译并行。
