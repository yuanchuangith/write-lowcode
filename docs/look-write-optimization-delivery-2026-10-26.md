## 响应减量与旧值引用

MCP 默认 summary，显式 full 保留；Python 服务内部兼容入口保留完整默认值。显式 include_context 的原语义优先。上下文支持精确 parameter_paths、按需完整值和报告单字段读取。read_edit_value 的 offset 为 Unicode 码点位置，预算按 UTF-8 字节计算，默认 16 KiB、上限 64 KiB。碎片必须校验绑定和指纹，拼接后解析。外层 MCP 包装和 telemetry 不属于单字段服务预算。

guard_ref 与完整 expected_old_value 二选一。独立用途的签名绑定会话、所有权修订、基线、关系、编译器、目标、路径和数组选择器。服务从不可变基线恢复完整旧值，再进入原预检、原子参数检查、原生生成和审批；批次中间结果仍用完整旧值。篡改、跨会话、所有权变化、草稿、relations 和编译器漂移均有阻断测试。

最终六类合成完整 MCP 流程覆盖长表达式、两层父节点、四个目标重复契约、大数组和报告大单项。返回字节减少 **92.754%–97.483%**，每条流程均为 7 次调用，候选、计划绑定、审批候选和完整复核哈希一致，无预先同意。详见[最终附件](payload-reduction-final-2026-10-26.json)和[第一批历史测量](payload-reduction-results-2026-10-26.md)。

Look 过滤器和异常输出使用有界摘要、完整当前页及证据版本绑定游标；超大单项支持规范 JSON 分片。重复异常候选只在顶层 runtime_published_candidates 出现，调用方需随此公开字段变化更新。摘要和截断证据不能证明完整内容或案例缺失。

## 服务耗时与实验边界

Write 合并 begin 相邻 binding 消费、prepare 重复 grants 查询，并将 prepare 编译器检查放在草稿及 relations 读取之后。公开 status 完整检查；私有延后状态不宣称 write_ready。Node 前后、独立复验、C# 校验和写入边界保留原检查。新增回归覆盖延后状态失败路径、备份后编译器失败、读取草稿后来源漂移。

共享完整画布校验只保存所需位置，分页只构造当前页，仍检查隐藏节点的重复 Key、非法层级、未知元素及参数。万节点样例五轮完整输出 hash 一致，峰值分配由约 7.3 MB 降至 1.3 MB（约 82%）；tracemalloc 下的局部时间不代表整体工具提速。原始[基线](discovery-pages-baseline-2026-10-26.json)和[候选](discovery-pages-candidate-2026-10-26.json)保留。

Look 去除未用 C# 正文，使用请求内符号/邻接表和 deque，图查询 SQL 提前过滤、批量读取别名/支持、减少重复序列化，增加 SQL/Python 工作预算。中断明确不完整、计数未知，不报告全局孤岛或案例不存在。完整案例保留全部支持，与展示的代表支持分开。五轮成对中位时间：图快照 62.93→51.01 ms、检索 171.18→48.22 ms、后端追踪 1027.86→64.63 ms；完整输出 hash 每轮一致。这是合成 SQLite/内存索引工作负载，不能推广为真实业务端到端倍数。详见 `../look/docs/speed-accuracy-implementation-20261026.md`。

独立 Node / net9 C# 探针五轮中位数：串行 6587.332 ms，并行 3970.548 ms（约 39.7% 改善）。该探针是独立合成 C# 类，没有生产混合候选、可靠尾延迟和全部失败/清理覆盖。因此合入条件没有全部通过，服务保留串行。[探针附件](validation-overlap-probe-2026-10-26.json)记录未验证项。

### 同机交替服务基准

基线与候选各五轮，共 240 次请求，每条流程包含 begin、发现首页、发现末页、context、plan、prepare 六次调用。真实 Node 编译器，模拟业务仓库与审批窗口，临时真实本地 SQLite，候选 data/JS/C# 和 relations 哈希跨实现及各轮全部相同。下面的完整链耗时按每次实际六次请求之和计算中位数，不能通过相加各工具中位数得到。

| 规模 / 初始缓存 | 基线完整链中位数（范围） | 候选完整链中位数（范围） | 中位数改善 |
| --- | ---: | ---: | ---: |
| 6 节点 / 冷 | 15.320 s（14.699–19.849） | 14.841 s（13.463–15.468） | 3.1% |
| 6 节点 / 热 | 14.005 s（13.162–14.506） | 12.800 s（12.038–13.256） | 8.6% |
| 1000 节点 / 冷 | 17.196 s（16.355–18.090） | 16.101 s（15.388–17.888） | 6.4% |
| 1000 节点 / 热 | 15.718 s（14.700–16.647） | 14.676 s（14.182–15.785） | 6.6% |

prepare 中位数分别为 3092→2563、3048→2567、3599→3194、3739→3170 ms，改善 11.2%–17.1%。begin 来源扫描从冷 9→8、热 7→6，prepare 从 5→4；完整链从冷 26→24、热 24→22。模拟 grants 查询从 3→2。真实本地 SQLite 仍为 44 语句，Node 子进程冷 11、热 10，Git 子进程 30；没有通过省略独立 Node 复验来提速。

没有全部阶段都改善：千节点热末页发现从 911→1047 ms（约慢 14.9%），热 plan 从 5549→5590 ms（约慢 0.7%）。原始来源绑定和 Git 阶段存在波动，不能从五个样本证明没有回归，也不能据此声称整体服务的稳定尾延迟。每阶段的五次中位数、最小/最大值、计数和字节均在[原始成对附件](service-pipeline-pairs-2026-10-26.json)。本机后台负载未严格隔离。

服务基准为兼容性使用 begin/context 的内部完整默认值，且新增 telemetry 元数据，所以小配置六次响应字节中位数约增加 2.4 KiB。它没有测量大配置默认 MCP 摘要的减量；后者由前面的六类七次 MCP 流程单独验证。服务基准的 C# 为空，不能代表实际混合 C# 场景。
