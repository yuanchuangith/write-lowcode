# 按动作分组增量生成

普通草稿编辑从会话内保存的画布、JS、C# 和关联数据出发，只重新生成变动的动作分组以及引用这些分组的依赖分组。最小边界是完整动作函数；分组内部的 IF、变量声明、返回值和原生元件仍完整生成。不会按代码行拼接业务表达式，也不会为通过检查自动重命名回调或删除旧编排。

原生生成器拿到完整候选画布，仅限制遍历生成的分组，避免子动作、跨语言调用丢失上下文。依赖从参数中的本地动作引用提取并计算传递闭包，包含计时器和生命周期事件；共享上下文改变时全部重新生成。未变分组保留保存时的源文本，未变分组关联数据沿用会话快照。

JS 用 Babel AST 定位工厂直接声明的动作函数，避免把嵌套业务赋值、字符串或注释当作替换位置。C# 用保守词法扫描定位原生方法，支持常规、逐字和插值字符串；暂不支持 C# 原始字符串。边界、组标识或旧源码无法确认时，明确阻塞并保留旧数据，不自动全量生成或改造业务代码。

所有候选 JS 都检查完整语法并扫描词法引用。未变且原样保留分组中的旧未声明引用记录在 `baseline_diagnostics`，状态为 `unverified`，不能据此声称运行正确；这些旧问题不阻塞本次局部修改。改动及依赖分组中的未声明引用仍阻塞，`inbiz` / `Inbiz` 保留名和平台挂载覆盖保护不变。旧 `eval(...)` 原样保留，场景执行器继续拒绝动态代码执行。

独立进程从同一保存基线和候选画布重新计算依赖、运行原生生成、合并源文本，并逐项比较完整 JS、C#、关联数据、生成范围、事件和接口元数据证据。审批前再次执行该流程。生成证据绑定完整基线、候选、生成分组和保留分组，并纳入计划和事务签名。保存基线的关联数据发生并发变化也会阻塞。完整候选 C# 强制编译、人工审批及保存后复核继续保留。

显式的历史引用修复流程继续执行完整生成，避免把待修复引用当作未变基线保留。未提供保存基线的底层编译接口也维持完整生成，用于原生生成测试和维护；MCP 普通草稿规划固定从会话快照取得基线，不向模型开放跳过检查或自选基线参数。

这次只修改工作区源代码，不安装插件、不变更版本、不重启 Codex，也不保存或发布业务草稿。
