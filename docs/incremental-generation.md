# 全量与增量生成

同一分支支持 `generation_mode="full"`、`"incremental"` 和 `"auto"`，不需要分别维护两套插件。`plan_canvas_patch` 默认使用 `full`；用户可以在对话中指定模式，由 agent 传入工具参数。

| 模式 | 生成范围 | 未声明引用检查 |
| --- | --- | --- |
| `full`（默认） | 完整候选画布中的全部动作分组 | 所有分组的未声明引用均阻塞 |
| `incremental` | 变动分组及受影响的依赖分组，其余保存源码原样保留 | 重新生成分组的未声明引用阻塞；原样保留分组的旧问题记录为“未验证” |
| `auto` | 根据实际改动及依赖范围选择全量或增量 | 按最终实际模式执行 |

用户明确指定模式时，agent 必须遵从。没有指定时保持全量默认，也可以根据任务主动为小范围修改选择增量，或交给 `auto` 判断；进入审批前说明实际采用的模式、影响范围和选择原因。检查失败、非法事件绑定或编译错误不会触发另一种模式的静默重试。

对话示例：

- “这次用全量生成。” → `generation_mode="full"`。
- “只改这个按钮，用增量生成，其他分组保留。” → `generation_mode="incremental"`。
- “你按改动范围选择全量或增量。” → `generation_mode="auto"`，审批前报告实际选择。

`auto` 在保存基线和原画布完整、共享元数据未变、动作类型和语言没有转换时，按实际画布差异及传递依赖统计范围。只有同时满足以下条件才选择增量：受影响分组（含依赖和删除分组）不超过 3 个，实际新增、删除或变更节点不超过 30 个，且受影响分组占前后画布分组合集的比例小于 50%。其余情况选择全量。该策略版本为 `action_groups_v1`，选择原因和统计值写入 `generation_selection`；操作条数和用户描述长短不参与判断。

增量生成从会话内保存的画布、JS、C# 和关联数据出发。最小边界是完整动作函数；分组内部的 IF、变量声明、返回值和原生元件仍完整生成。不会按代码行拼接业务表达式，也不会为通过检查自动重命名回调或删除旧编排。

原生生成器拿到完整候选画布，仅限制遍历生成的分组，避免子动作、跨语言调用丢失上下文。依赖从参数中的本地动作引用提取并计算传递闭包，包含计时器和生命周期事件；共享上下文改变时全部重新生成。未变分组保留保存时的源文本和会话快照中的关联数据。

JS 用 Babel AST 定位工厂直接声明的动作函数，避免把嵌套业务赋值、字符串或注释当作替换位置。C# 用保守词法扫描定位原生方法，支持常规、逐字和插值字符串；暂不支持 C# 原始字符串的增量拼接。增量所需的边界、组标识或旧源码无法确认时，明确阻塞并保留旧数据；不自动改造业务代码或用全量掩盖失败。

两种实际模式都检查完整候选 JS 语法和保留名、平台挂载覆盖。增量模式中，未变且原样保留分组的旧未声明引用记录在 `baseline_diagnostics`，状态为 `unverified`；这些旧问题不阻塞本次局部修改，也不因此成为合法全局变量。重新生成分组中的未声明引用仍阻塞。全量模式检查所有分组的未声明引用。`inbiz` / `Inbiz` 保留名保护不变；旧 `eval(...)` 表达式不为适配工具而重写，场景执行器继续拒绝动态代码执行，无法验证的场景不得标为通过。

独立进程从同一保存基线和候选画布重新确定实际模式和依赖范围、运行原生生成、重建完整候选，并逐项比较完整 JS、C#、关联数据、生成范围、事件和接口元数据证据。审批前再次执行该流程。模式、选择原因、生成分组、保留分组及基线和候选指纹纳入计划和事务签名。保存基线的关联数据发生并发变化也会阻塞。两种模式均保留完整候选 C# 强制编译、人工审批及保存后复核，没有跳过检查参数。

显式的历史引用修复流程继续执行完整生成，避免把待修复引用当作未变基线保留。未提供保存基线的底层编译接口也维持完整生成，用于原生生成测试和维护；MCP 普通草稿规划固定从会话快照取得基线，不向模型开放自选基线参数。

本次只修改工作区源代码，不安装插件、不变更版本、不重启 Codex，也不保存或发布业务草稿。
