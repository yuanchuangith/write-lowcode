## 原审查快照

审查基于提交 `6a07207`。本轮仅检查技能合同、工具调用链和默认体验，运行合成画布与 Qt 离线复核；未调用业务 MCP、连接业务数据库、改变安装配置或功能开关。

## 需要明确设计边界的下一批

### 严格修改范围

当前超范围变更只增加 scope_unverified，未构成失败（`logic_review.py:132`、`:277`）；`service.py:680` 将所有非 failed 结果视作可进入人工审批。

离线合成例子已确认：只要求修改 query.status，但同时改动另一个节点的输出；目标配置断言通过，额外变更为待验证，candidate_gate.blocked 仍为 false。初次未提供 review_spec 也可得到待验证而非阻断的报告。这是现有人工核对策略，不等于绕过人工审批或直接写入。

建议新增严格范围策略：普通自动规划明确要求有验收规则，明确在范围外的变化默认阻断；保留有明确标识的人工核对方式。不要把所有 unverified 都阻断，否则 C# 未做真实业务执行等正常边界也会使工具无法使用。该项属于行为合同调整，本轮没有启用。

### 同一请求内复用编译上下文

`service.py:97` 每次 `_components` 都创建新 CompilerBridge；入口与 editor_status、prepare_write 内部还有重复创建。`compiler.py:292` 的复核分别启动事件检查与独立再生成。

已有 profile 对独立 compile + verify 的测量是 3 次 Node、5 次 manifest 校验，合计约 4,139 ms，其中 manifest 约 975 ms；不是完整会话或端到端耗时，见 `generation-quality-and-speed.md:14`。

建议先限于单个工具请求复用验证上下文，再将事件复核和独立再生成放入一次新的复核进程，保留第二次生成及阶段前后的来源核对。验收需要完整产物相等，以及处理中替换 source、bridge、adapter 必须失败。跨会话长期复用及直接复用 C# 构建成功证据暂不默认开启。

### 相同值不产生新计划

`canvas_operations.cjs:188` 检查原值后，没有排除新旧完全相等的 set_parameter，仍执行原生生成。建议只对这种明确子集，在检查身份、路径及原值后剔除无变化操作；整批无变化时返回 no_changes，不创建审批。旧值已过期仍必须拒绝，不能先比较新旧请求值就跳过并发检查。

### 具有唯一身份的数组项修改

目前数组只支持完整替换，禁止索引路径（`canvas_operations.cjs:180`）。40 条条件只改一条时，仍需提交完整旧、新数组。

可新增由原生唯一行 key 定位的数组项操作，要求唯一命中和完整旧项前置条件。没有稳定 key、重复候选或原生合同不明确时继续使用整体数组；不要引入按显示文本猜测目标或裸索引修改。验收覆盖重排行、重复条件、嵌套 AND/OR 和旧值变化。

### 会话内继续的授权规则

`SKILL.md:12` 要求当前消息显式调用技能，`:13` 把“继续”排除；`:95` 又允许用户请求继续后重开审批窗口。两者对同一会话的解释存在冲突。

建议明确区分首次激活与已授权同一会话的继续，允许在既有目标上查询状态、重开、验证及结束；改变目标或超出既有授权仍按原规则处理。保留 allow_implicit_invocation=false，避免诊断建议自动触发新编辑。此项需要按既有用户偏好单独决定，本轮没有修改触发或授权策略。

## 不建议关闭或扩展

- 保留原生编译、独立再生成、非空 C# 编译、备份、来源绑定、并发核对和人工审批；已有数据不足以支持通过跳过它们提速。
- 不建议为提速移除已声明的 JS 回归场景。纯 C# 画布的 JS 源码为空时已经直接返回待验证，不启动 JS 子进程（`logic_scenarios.py:201`）；这一项无需重复优化。
- 暂不扩展为自由 SQL／JSON 写入、自动发布、真实业务 C# 执行或基于同名字段的广泛自动修复。这些能力不能直接解决当前已证实的耗时与定位问题。
