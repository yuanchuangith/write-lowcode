# 编辑技能离线行为验证（2026-10-26）

本轮独立代理只读取技能和相关参考，按原始用户请求及模拟工具响应决定下一步。没有提供预期答案，没有调用业务 MCP、数据库或审批窗口。下表记录实际演练结果；它不证明线上运行或完整业务覆盖。

| 场景 | 实际下一步与结果 |
| --- | --- |
| 首次对话只说“继续照方案改”，未显式启用编辑技能 | 不调用任何编辑工具，指出首次显式启用要求。 |
| 已授权会话中继续，原事务窗口仍在启动 | 等待返回的 1000 ms 后查询同一事务，不新建会话、计划或窗口。 |
| 本次 `no_changes=true`，另有旧 ready 计划 | 停止本次规划，不审批或自动取消旧计划。 |
| 保存已完成，关系图提议曾被拒绝，用户只问保存状态 | 复用完成凭据和拒绝状态，不重复查图或询问。 |
| 已同意修改 A→B，完整案例还包含 A→C | 从完整快照合并，仅修正 A→B，保留 A→C 和有效证据，提交快照 token；收到真实成功回执才记录结果。 |
| 保存后的关系变化尚未发布 | 记录 `pending_publication`，说明缺少当前发布证据，不把草稿当作已发布事实，不提前询问图更新。 |

六个场景均走到相应分支，未发现决策缺口。工具端另有临时 SQLite、模拟编译器和本地 MCP 回归：节点同名与分页、草稿/归属变化、复核状态持久化与版本冲突、拒绝后重问拦截、队列部分成功、完整案例更新及过期 token 拒绝。静态合同测试仅保留元数据、显式调用策略、本地文件/章节链接、入口大小和关键协议标识等结构要求。
