# 对话编辑操作衔接修复

本轮按源码审查发现修复操作断点，保留对话直接打开正式审批、人工确认保存、核验释放和队列复用窗口。仅交付 Write 源码及技能镜像，不安装本地插件、不重启 MCP、不操作现有业务状态。

## 行为变化

- 旧会话核对返回 unknown 或未释放时保留窗口并显示原因，不再误报完成。重开、核对、取消和释放在后台执行，确认弹框和心跳留在界面线程，忙碌时防止重复操作。
- 新建的空操作会话在 SQLite 控制事务中确认没有任何计划/事务后结束。并发或已有计划继续保留，响应明确返回 session_released 与后续入口。
- finished 保存可重新发起原备份恢复审批：一致快照核对当前草稿和关系与保存回执，原子重获占用，拒绝冲突和后续保存历史。新的恢复仍需完整编译证据和人工审批，取消不丢失原保存记录。
- 队列失效候选仅在可证明未执行时隔离，健康项可继续；保留其审批记录。身份和执行未知仍阻断。
- 执行前校验失败保留结构化原因，明确取消失效审批再规划；不再引导到不适用的执行结果恢复。
- 补读提示携带 conversation_id、目标和计划参数；抽象 next_action 配实际入口；失败回执统一错误及兜底字段，不加入签名工件。
- read_plan_review 的完整行遵守显式预算，超大行转摘要及精确字段读取，不截断旧值或扩大预算返回整行。
- 编译来源的 Git、Node 和 SDK 探测隐藏 Windows 控制台，保留实际命令、超时和前后来源校验。

## 技能发现边界

Write 保留现有 allow_implicit_invocation=false。该配置要求显式启用，不应为了出现在隐式技能列表而放宽编辑授权。仓库技能、镜像和插件元数据进行本地检查；当前会话是否重新加载安装版本不由源码修改证明。本轮不以重装处理技能清单现象。
