# 规划、范围校验和保存复用修复

版本：`0.1.55+codex.local-20261029-planning-workflow`。本次交付仓库源码，不更新运行中的客户端或操作业务草稿。

| 原问题 | 修改后行为 |
| --- | --- |
| 超过 100 项才发现无法规划 | 移除操作条数限制，入口公布统一体积预算 |
| 分批规划丢失前一批候选 | `append_to_plan_id` 合并最新计划的操作；完整候选统一复核、审批 |
| 新分组和节点无法声明验收范围 | 要求、断言及场景通过原生生成记录解析别名；原始要求与真实目标同时绑定 |
| 新节点断言因修改前不存在而失败 | equals/contains 核对候选；unchanged 仍要求原节点存在 |
| 路径开头 `/` 导致校验结论冲突 | 统一规范化和范围包含规则 |
| 修正无效定位仍要求新业务依据 | 可证明的无效 key 修正复用原要求；已存在目标的范围扩大仍需依据 |
| 20 个场景、连续 10 步的硬门槛 | 取消数量门槛，保留体积和执行时间预算 |
| 无关文档修改使整个会话失效 | 编译绑定只覆盖相关输入字节；Git 元数据仅供追溯 |
| 审批和保存重复启动生成、编译及探测 | 复用已绑定结果；源文件或引用变化时拒绝复用或重新编译 |

同一次原生生成返回的确切内存对象和内容指纹用于复核，避免规划时立即再生成一遍。拷贝导入的候选沿用重新生成检查；原对象被修改会直接拒绝。来源检查的同机五次样例中位数：加载目录绑定约 1.20 秒、2 次子进程；直接比对输入字节约 0.67 秒、0 次子进程。此对比仅测来源检查阶段。

同机交替五轮的单变量原生画布样例中，重复生成复核的中位耗时约 2.80 秒；复用同次原生输出并检查指纹约 0.16 毫秒。该结果表示移除重复工作的阶段耗时，不表示整个规划、页面操作或保存都只需该时间。

离线组合流程使用现有真实原生编译器：102 项创建操作，追加为 103 项，新增分组及节点别名、21 个场景且每个连续 11 步；无效批次失败后修正继续，最终生成一条主记录审批。审批准备样例约 0.97 秒，未再次运行生成器。场景结果均通过，没有连接业务库或执行审批 SQL。

定向回归覆盖越界仍阻断、原要求不可放宽、无效批次不污染检查点、过期计划不可追加、操作清单篡改、来源变化、引用变化、MCP 实际输入输出转换及保存协议。性能样例仅代表本地阶段耗时，不代表实际页面生成或数据库保存的端到端耗时。
