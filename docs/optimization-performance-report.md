# 交接、预检和编译准备实测（2026-10-22）

本页保留第一轮历史测量。后续优先级优化已允许普通 Candidate.cs 错误保留经核实的 restore 环境；本页“错误后冷重建”描述的是当时版本，后续复测见 [优先级优化测量](priority-optimization-measurements.md)。

本轮用本机合成画布测量新增缓存和预检路径：6 个 JavaScript 分组，各含 1 个 SetVariable 元件；小改修改 1 个元件，多处修改 6 个，错误修正场景提交 2 条操作且第二条含非法字段。采用默认全量生成，不连接业务数据库，不执行生成的业务代码，不打开业务审批。

这是当前实现的冷、热路径比较，未在改动前取得相同脚本的基线。每个场景只测量一次，不能推断稳定提速比例或真实复杂业务耗时。模型推理、网络往返、数据库、业务检查和人工审批未测量；脚本没有调用模型或数据库。

## 原生生成

| 场景 | 总耗时 ms | 生成 Node | 注册表 Node | 独立复验 Node |
| --- | ---: | ---: | ---: | ---: |
| 小改，规则冷缓存 | 4932.373 | 1 | 1 | 1 |
| 小改，规则热缓存 | 3892.913 | 1 | 0 | 1 |
| 多处修改，规则冷缓存 | 5009.826 | 1 | 1 | 1 |
| 多处修改，规则热缓存 | 4380.208 | 1 | 0 | 1 |
| 第二条操作非法 | 0.535 | 0 | 0 | 0 |
| 修正后重交完整两条操作 | 4005.948 | 1 | 0 | 1 |

小改的注册表阶段从 1113.727 ms 降至 4.632 ms，多处修改从 1131.686 ms 降至 4.004 ms。这不包含其前置的内容绑定校验。小改和多处修改分别核对冷、热路径完整 JS 指纹相同；每次成功生成都启动独立新 Node 复验，没有缓存候选通过结论。第二条非法操作在完整生成前被发现；修正后仍从原始画布应用完整批次。

来源内容扫描和最终漂移检查继续执行；Git 证据每请求刷新。`timings` 中存在包含关系，例如注册表阶段包含其 Node 调用，不能将全部分段耗时相加当作总耗时。

## C# 工作区

采用本机 .NET SDK 9.0.204、net9.0、零应用 DLL 引用，直接调用编译辅助器，用实际 dotnet restore/build 验证工作区。此项专门测准备和构建成本，不代表业务 C#、独立探测协议或生产兼容性。独立探测、超时清理、两次完整候选编译与 DLL 漂移另由针对性测试覆盖。

| 场景 | 总耗时 ms | restore ms | 完整 build ms |
| --- | ---: | ---: | ---: |
| 首次冷编译 | 4707.894 | 969 | 3500 |
| 更换候选后的热编译 | 3350.006 | 未调用 | 3141 |
| 含语法错误的候选 | 1962.214 | 未调用 | 1781（失败） |
| 错误后冷重建并编译修正候选 | 4301.427 | 1125 | 2984 |

热路径实际执行 `build --no-restore --no-incremental`；编译失败使槽失效，下一请求冷重建。没有沿用旧成功结果。正常完成及受控超时会清理候选源码和编译输出；宿主硬崩溃的遗留在下一次租用时回收。

## 复现和后续测量

在 write 根目录运行（仅使用合成数据，不加载连接配置）：

```powershell
python scripts/benchmark_edit_pipeline.py `
  --frontend G:/hoyi/updateComponents/gxp2.components `
  --csharp --output output/optimization-benchmark.json
```

`--csharp` 是可选的，当前合成 C# 样本要求本机具备 net9.0 targeting pack。脚本只输出阶段、耗时、调用数量、缓存标记、指纹和错误码，不输出参数、完整代码或编译诊断。本轮完整分段数据见 [测量数据](optimization-benchmark-2026-10-22.json)，运行时原始输出保存在 `output/optimization-benchmark.json`。

真实业务后续可用两端响应中的 `trace_id`、`total_elapsed_ms` 和 `timings`，分别统计草稿读取、交接核对、预检、规则加载、生成、独立复验、引用核验、restore、build 与业务检查。模型与网络成本需由调用方另外测量。暂不引入常驻 Node 进程；待实际复杂场景重复样本足够后再决定。
