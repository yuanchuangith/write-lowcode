# GXP 表单配置编辑

使用独立的 `gxp-form-config-editor` MCP 服务处理表单设计配置。本技能可根据用户的自然语言请求启用；读取技能、检查设置和诊断本身不授予保存权限。用户已经明确的修改要求可以继续规划，不重复要求启用。每次实际保存仍须用户在本地审批窗口核对并确认。

本技能与 `$gxp-lowcode-edit` 属于同一安装包，但对话、会话、计划、审批签名和业务状态独立。编排编辑的授权、备份、计划和已批准事务均不能用于表单保存。

## 范围

- 修改已有组件的允许属性，包括必填、只读、默认值、布局、数据源与组件过滤开关；实际支持的组件、路径和适配器以当前组件目录及工具响应为准。动作生成的动态过滤和共享数据集条件不在本技能范围，详见[原生协议依据](references/native-protocol.md)。
- 每页建立独立会话，将该页已有组件的已确认修改合并为一次计划。
- 首版不新增、删除、复制或移动组件，不修改组件身份、类型、所属页面、动作脚本、页面主模型或发布状态。布局只改现有参数，保留父子关系与次序。
- 已保存草稿与实际运行是不同阶段；本技能不自动发布，也不把配置检查通过描述为整页运行验证通过。

## 工作流程

1. 调用 `create_form_conversation` 一次，后续调用沿用本对话标识。检查 `form_editor_status`，缺少连接时按[连接与保存](references/connection-and-save.md)处理。
2. 以当前工具支持的页面标识调用 `begin_form_edit_session`。核对环境、页面和草稿身份，保留返回的会话及不可变备份；不要把动作 code 当作页面标识。
3. 使用 `find_form_components` 定位组件，核对 ID、类型、标题、父组件和路径。通过 `inspect_form_component` 查看允许的操作及属性；仅在需要精确旧值时使用 `read_form_value`。
4. 根据用户原始要求固定修改目标和应保留的行为。按[操作契约](references/operations.md)生成结构化修改，旧值使用完整 `expected_old_value`，不凭摘要、相似名称或推测构造组件配置。
5. 调用 `plan_form_patch`；通过 `read_form_plan` 分页核对 `changes` 和 `requests`，确认组件属性前后值及实际保存请求与要求一致。失败应读取对应原因并修正当前范围内的问题，不改变验收要求使候选通过。
6. 准备完成后调用 `prepare_form_write` 打开正式本地审批窗口。模型没有审批或直接执行工具；由用户在窗口内核对环境、页面、属性差异及请求并确认保存。
7. 通过 `get_form_write_status` 核对结果；只有 `verified=true` 且 `session_released=true` 才报告草稿保存完成。发布和设计器内的实际效果仍需单独核对。

## 平台协议与失败处理

当前原生草稿、并发和关联保存协议尚未验证时，服务必须返回 `write_ready=false`。此时保留可用的定位、读取和离线计划结果，报告缺少的具体平台证据；不得改状态、伪造验证结果，或退回动作编辑器、SQL、任意 HTTP 请求执行保存。

平台协议需通过用户已连接的目标 Origin 和实际表单设计器补证。只有就绪响应明确支持的原生草稿保存路径可进入审批；组件路径校验和变更检查不等于完整设计器校验器。

状态为 `uncertain` 或保存结果未核实时，先调用 `recover_form_edit_session` 核对，不能重试原请求推测成功。用户取消用 `cancel_form_edit_session`；恢复原配置使用本会话不可变备份，通过 `plan_form_restore` 生成恢复计划，仍经过人工审批。取消本地流程不表示已提交的修改被撤销。

连接、登录、发布协议和恢复细节见[连接与保存](references/connection-and-save.md)。
