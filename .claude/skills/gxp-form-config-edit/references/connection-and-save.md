# 连接、保存与恢复

两个 MCP 服务共享安装包、venv、经过 manifest 验证的运行快照和进程租约；表单使用独立的 `form-config` 业务状态与审批 domain。不要导入或迁移编排会话、编排审批工件及 SQL。

## 连接与原生协议

先检查 `form_editor_status`。需要设置或登录时调用 `form_connection_settings` 支持的本机入口。账号、密码、令牌、Cookie 和连接秘密由本地窗口处理，不要求用户将其粘贴给模型，不打印或读取秘密存储。

已启用项目管理时，表单服务加载当前项目的 `platform_binding.form_config`，使用与该项目登录一致的凭据引用；状态中的 `connection_source=active_project` 表示使用项目连接。设置入口打开统一项目窗口，不再读写旧的独立配置来覆盖项目。未启用项目管理时保留独立连接入口。共享连接不共享编排会话、备份、计划或审批。

连接可用与协议就绪分开判断：读取只要求 `read_ready=true`，不要求 `write_ready=true`。当前项目没有原生读取契约或证据时仍如实报告缺项，不能从旧项目补入协议，也不能手工改 readiness 标记。`/api/app_info` 连接探测成功仅证明当前应用及站点可访问，不代表表单草稿协议已经验证。

JS Reverse 连接用于查看用户授权 Origin 上的实际表单设计器和保存行为，不能把已连接 Origin 当作页面保存协议已经确认。需确认页面草稿身份、版本或其他并发条件、关联记录、原生请求与保存后读取方式。证据不足时 `write_ready=false`；不能切换到已发布配置、无并发条件的更新或任意请求写入。

服务返回的 readiness 是当前协议是否可保存的依据。离线规划和组件属性校验可以在可用范围内进行，但它们不授予写入能力，也不代表平台全页校验。

## 审批与保存

`prepare_form_write` 准备并打开本地人工审批。窗口展示该表单的环境、页面、组件属性变化与原生保存请求；用户在窗口内确认才可执行。审批绑定本次 form domain、目标、原值、候选和请求，不能继承编排审批，也不能跨计划或环境重用。

会话可处于 `active`、`planned`、`reviewing`、`executing`、`uncertain`、`saved` 或 `cancelled`。不要只凭 `saved` 或窗口关闭推断执行结果，保存完成必须同时满足：

- `verified=true`：保存后的读取结果与批准候选一致。
- `session_released=true`：该会话已核对并释放。

并发变化、草稿身份或保存协议改变应阻止执行，重新读取实际目标后再规划。保存后只报告已验证的结果，不声称已发布或线上行为已通过。

## 结果不确定、取消与恢复

`uncertain` 表示可能已发出请求而尚不能证明提交结果。先使用 `recover_form_edit_session` 读取并归因；不能再次提交原保存请求来探测结果。恢复仍不确定时报告当前证据和缺失的读回条件。

`cancel_form_edit_session` 取消允许取消的本地会话，不撤销平台已经完成的保存。恢复配置使用 `plan_form_restore`，限本会话已验证的不可变备份，并再次核对当前草稿及并发条件、差异和人工审批。不要覆盖其他会话后来修改的内容。

恢复只逆向处理原人工批准且已核实保存的属性差异，包含派生属性及新增属性的移除；只有原签名记录确认新建的空父容器才会清理。恢复还核对保存回执签名、组件目录和引用资源版本，候选必须精确还原签名备份。后续修改、合约变化或资源失效时拒绝恢复，不覆盖整页，也不绕过属性目录。恢复计划不自动再次取反；需要继续调整时针对当前配置提出新计划。

原生协议与组件目录的来源、已捕获字段及尚未验证的写入条件见 [native-protocol.md](native-protocol.md)。
